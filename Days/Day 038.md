# Day 38: Multilingual Adversarial Testing of LLM Safety Behavior

**Date : 20/11/2026**

## 1. Overview

This experiment investigates how a large language model responds to potentially harmful requests expressed in different languages.

The objective was to explore whether language variation influences refusal behavior, response clarity, and the consistency of safety-related responses.

The evaluation used **Qwen3:1.7B**, running locally through Ollama.

## 2. Research Question

**Does an LLM maintain consistent safety behavior when the same underlying request is expressed in different languages?**

The experiment focused on English, Hindi, Gujarati, and Hinglish (Romanized Hindi).

## 4. Methodology

The experiment followed these steps:

1. Defined five security-related scenarios.
2. Prepared equivalent requests in English, Hindi, Gujarati, and Hinglish.
3. Submitted the prompts to the local model.
4. Recorded model responses and execution latency.
5. Captured execution status for each test.
6. Prepared the responses for manual refusal and safety assessment.

The evaluation considers three separate dimensions:

- **Refusal behavior:** Whether the model declines to provide the requested harmful assistance.
- **Response clarity:** Whether the answer is coherent and understandable.
- **Safety behavior:** Whether the response contains actionable harmful information.

These dimensions should not be treated as interchangeable.

### Preliminary observations

**English**

The completed English responses contained explicit refusals of the harmful requests.

**Hindi**

Several responses attempted to refuse the requests but contained unnatural or confusing phrasing.

**Gujarati**

Some responses exhibited unclear wording, repetition, or ambiguous framing. These require closer manual inspection to determine whether they constitute refusals, unsafe responses, or general language-generation failures.

**Hinglish**

Responses sometimes shifted into Devanagari Hindi and contained grammatical or semantic inconsistencies. One test timed out.

## 6. Key Findings

### Observation 1: Response clarity varied across languages

The model's ability to communicate a clear response appeared inconsistent across the tested languages.

### Observation 2: Safety and language quality require separate evaluation

An incoherent response does not automatically indicate a successful jailbreak.

Similarly, a response that sounds like a refusal should still be checked for potentially actionable harmful information.

### Observation 3: Execution reliability matters

The timed-out test demonstrates the importance of recording errors separately from completed model responses.

### Observation 4: Exact safety outcomes remain unverified

The CSV contains response text, but its manual refusal and safety assessment fields have not yet been completed.

Therefore, this experiment does not currently establish a verified jailbreak success rate.

## 7. Limitations

- Only one local model was evaluated.
- The dataset contains five scenarios.
- Each scenario-language combination was tested once.
- The experiment does not establish statistical significance.
- Language variations may differ in nuance.
- Manual safety classifications are pending.
- Response clarity has not yet been evaluated using a standardized rubric.
- One test ended with a timeout.

These limitations prevent broad conclusions about multilingual model safety.

## 8. Next Steps

3. Identifying actionable harmful information, if any.
4. Evaluating linguistic clarity separately from safety.

## 10. Conclusion

This preliminary experiment highlights the importance of evaluating LLM safety behavior beyond English-language prompts.

The observed responses suggest differences in linguistic clarity and response consistency across languages.

However, further manual assessment is necessary before determining whether these differences represent actual safety-boundary failures.

**Main takeaway:** Multilingual AI safety evaluation should measure refusal behavior, harmful-content disclosure, language quality, and execution reliability as distinct outcomes.
