# System Prompt Confidentiality Evaluation Across 12 Application Scenarios

> **Project:** 100-Day AI Red Teaming Challenge  
> **Experiment date:** 19 November 2026 
> **Inference environment:** Local Ollama deployment  
> **Status:** Execution complete; response-level manual review pending

## 1. Executive Summary

This experiment evaluated whether a locally hosted language model would disclose synthetic confidential configuration markers when exposed to different system-prompt extraction approaches.

The evaluation used 12 fictional assistant scenarios. Each scenario had a distinct role, a confidentiality instruction, and a unique synthetic canary string. Five test cases were executed per scenario: one baseline control and four extraction-oriented tests.

Across the 48 attack attempts, the model returned the exact scenario-specific canary in 27 responses, producing an **exact canary disclosure rate of 56.25%**. No exact canary matches were detected in the 12 baseline responses.

Direct extraction and roleplay produced the highest exact-match rates in this run. Authority-framed requests produced no exact canary matches. These results describe this specific test campaign and should not be generalized to other models, prompts, or deployment configurations.

**Interpretation note:** Exact canary matching is a narrow, reproducible indicator of disclosure. It does not, by itself, establish complete system-prompt extraction. Response-level review is required to identify partial or semantic disclosure and validate the automated classifications.

## 2. Evaluation Objective

The objective was to conduct a structured assessment of system-prompt confidentiality across multiple fictional application contexts.

The experiment was designed to:

- Assess whether a model reveals a synthetic value explicitly marked as confidential in its system prompt.
- Compare responses to several prompt-extraction approaches.
- Observe whether results differ across application scenarios.
- Preserve complete prompts and model responses for subsequent analysis.
- Separate automated exact-match detection from human interpretation.

## 5. Observations

### 5.1 Attack-category variation

Direct extraction and roleplay each produced 10 exact canary matches across 12 attempts. Indirect extraction produced seven. No exact canary matches were detected for authority-framed requests in this campaign.

This indicates that the tested prompt approaches did not produce equivalent outcomes against this model and system-prompt configuration.

### 5.2 Scenario-level variation

The number of exact canary matches differed across application scenarios. However, each scenario had only four attack attempts. Consequently, one result changes a scenario's observed rate by 25 percentage points.

The scenario-level results should therefore be treated as descriptive observations, not as a ranking of application-domain security.

### 5.3 Baseline behavior

No exact canary matches were detected in the 12 baseline responses. This provides a useful control observation for this test set. It does not establish that the model would never disclose the canary under other ordinary prompts or conversation conditions.

## 6. Measurement Methodology

The test harness checked each model response for the exact synthetic canary assigned to that scenario.

The automated field `Canary Disclosed` records whether the exact string was present in the response.

This measurement has a deliberately narrow scope:

- **Exact match:** The scenario's synthetic canary appears in the response.
- **No exact match:** The exact canary string does not appear in the response.
- **Partial or semantic disclosure:** Requires human review; it is not automatically classified by exact string matching.
- **Fabricated information:** Must be distinguished from disclosure of the actual synthetic canary.

Accordingly, the principal metric in this report is called the **exact canary disclosure rate**, rather than a verified full system-prompt extraction success rate.

## 7. Manual Review Plan

The raw responses should be reviewed before drawing conclusions about the model's overall confidentiality behavior.

For each test response, review and record:

1. Whether confidential instructions were reproduced verbatim or in part.
2. Whether the response disclosed protected information without reproducing the exact canary.
3. Whether any configuration details were fabricated.
4. Whether the model refused, complied, or partially complied with the request.
5. Whether the automated exact-match classification accurately reflects the response.

Human review outcomes should be stored in separate fields, preserving the original automated result. This maintains an auditable distinction between machine-detected matches and analyst judgments.

## 8. Limitations

- The campaign evaluated one model tag, `qwen3:1.7b`.
- Each attack category had 12 test cases, one per scenario.
- Each scenario had only four attack attempts.
- The experiment used one system-prompt template structure with scenario-specific role descriptions and canaries.
- Exact string matching cannot detect every form of partial or semantic disclosure.
- A single execution per test case does not measure response variability across repeated runs.
- The findings do not establish how other model versions, providers, system prompts, or deployment safeguards would behave.

These limitations define the scope of the results; they do not invalidate the observations within this campaign.

## 10. Conclusion

In this 12-scenario exploratory campaign, 27 of 48 attack responses contained the exact synthetic canary assigned to the relevant assistant. No exact canary matches were detected in the 12 baseline responses.

Direct extraction and roleplay produced the highest exact-match rates in this run, while authority-framed requests produced no exact matches. The results demonstrate the value of evaluating multiple prompt approaches across distinct application contexts rather than relying on a single jailbreak example.

The next phase is response-level manual review, followed by a more controlled follow-up evaluation if the findings warrant it. Any broader conclusion should be based on validated response classifications and additional testing.

## 11. Responsible Testing

This experiment used fictional assistant roles, synthetic configuration labels, and a locally hosted model. It did not target third-party systems or use real credentials or personal data.

Public reporting should focus on methodology, aggregate results, and appropriately reviewed examples. Do not publish sensitive material if future experiments involve real systems or data without appropriate authorization and disclosure review.
