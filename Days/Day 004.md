# Day 4: How Text Becomes Tokens

**Date:** 09/08/2026
 
**Topic:** How changing one word in a prompt changes model behavior
 
**Status:** First pass done, reruns pending. Test performed later, with some changes made.

## What I learned

An LLM does not read a sentence the way we do. The text is first cut into small pieces called tokens, and those tokens are turned into numbers. Attention then helps the model work out how the pieces relate to each other.

This matters for red teaming: if tiny changes to the text change the tokens, the model is getting a different input even when the sentence looks the same to us.

## What I tested

I took 20 normal sentences and made 4 small changes to each one:

- **ALL CAPS**: the whole sentence in capital letters
- **Extra spaces**: three spaces between every word
- **One typo**: two neighbouring letters swapped in the longest word
- **Lookalike letter**: the first a, e or o replaced with a letter from the Cyrillic alphabet that looks identical

Then I counted how many tokens each version became. I used the `cl100k_base` tokenizer (the one used by GPT-style models) through a small Python script. Other models split text differently, so the exact numbers will differ for them.

## Example

| Version | Text | Tokens | Pieces |
|---|---|---|---|
| Plain | Please summarize this article for me. | 7 | `Please`, ` summarize`, ` this`, ` article`, ` for`, ` me`, `.` |
| ALL CAPS | PLEASE SUMMARIZE THIS ARTICLE FOR ME. | 9 | `PLEASE`, ` SUM`, `MAR`, `IZE`, ` THIS`, ` ARTICLE`, ` FOR`, ` ME`, `.` |
| Extra spaces | Please   summarize   this   article   for   me. | 12 | `Please`, (spaces), ` summarize`, (spaces), ` this`, (spaces), ` article`, (spaces), ` for`, (spaces), ` me`, `.` |
| One typo | Please summarzie this article for me. | 8 | `Please`, ` summar`, `zie`, ` this`, ` article`, ` for`, ` me`, `.` |
| Lookalike letter | Pleаse summarize this article for me. | 10 | `P`, `le`, `а`, `se`, ` summarize`, ` this`, ` article`, ` for`, ` me`, `.` |

This example is from my first small test on one sentence. In the 20-sentence run the typo and the lookalike letter were placed differently (the typo swaps letters inside the longest word, the lookalike replaces the first a, e or o), so the counts for sentence 1 in the table below are not the same as here.

In the last row the "а" in "Pleаse" is the Cyrillic one. It looks the same, but the word is split into pieces instead of staying as one token.

## Summary

| Version | Average tokens | Changed vs plain |
|---|---|---|
| Plain | 8.8 | n/a |
| ALL CAPS | 12.1 | more tokens in 20 of 20 sentences |
| Extra spaces | 15.2 | more tokens in 20 of 20 sentences |
| One typo | 10.6 | more tokens in 19 of 20 sentences (1 stayed the same) |
| Lookalike letter | 10.7 | more tokens in 20 of 20 sentences |

- No change ever made a sentence shorter in tokens.
- Extra spaces had the biggest effect, adding up to 9 tokens.
- A single lookalike letter added 1 to 4 tokens, even though a person would not see any difference.
- One typo added between 0 and 3 tokens.

## What this means

The same request, written slightly differently, becomes a different set of tokens. The model never sees the text we see, only the tokens, so a change that looks small to us can look quite different to the model. This is one reason wording and formatting changes can change how a model behaves.
